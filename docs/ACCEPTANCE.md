# 구축 기준과 실제 검증 범위

제품이 없는 범용 하네스이므로 제품 UI/라우트 검증을 수행했다고 주장하지 않는다.
자동 검사는 tests/test_harness.py의 임시 프로젝트에서 실행한다. 결과·실행 ID는 VERIFICATION.md 참조.

| 계획 ID | 막는 실수·사전 상태 → 동작 → 기대 | 분류·검증 방법 |
|---|---|---|
| H-01 | 사용자 데이터와 TMP 두 개 → 하나 정리 → 사용자·다른 TMP 보존 | 초기화 조건부 / test_sandbox_only_own_run_deleted 자동 |
| H-02 | 빈 값·상위 경로·다른 마커·링크 → clean → 삭제 전 거부 | 초기화 조건부 / sandbox 관련 자동 검사 |
| H-03 | 개발 버튼 존재 → 최종 화면 실행 → 노출 없음 | UI 조건부 / 실제 제품 미존재, RELEASE_CHECKLIST 수동 |
| H-04 | 개발 페이지/API 존재 → 최종 주소 접근 → 미등록/차단 | 서버 조건부 / 실제 제품 미존재, 과제에서 통합 검사 등록 |
| H-05 | dev/제품 진입점 → 호출 경로 대조 → 같은 구현·역방향 의존 없음 | dev 조건부 / 실제 제품에서 코드 검토 |
| H-06 | 대표 입력 → 실제 제품 경로 → 필수 결과 | 제품 필수 / 서비스 미구현, 실제 과제에서 검사 등록 |
| H-07 | 기준 원본 → 검사 중/후 변경 → 감지·실패 | 원본 조건부 / originals 관련 자동 검사 |
| H-08 | 원본과 시작 코드 분류 → 시작 코드 수정 → 원본 검사 유지 | 시작 코드 조건부 / test_originals_unchanged_and_starter_edit_allowed |
| H-09 | 기록·미커밋 코드 → 새 세션 → 실제 지문 대조 | 필수 / 재개 지침 제공·변경 감지 자동, 별도 Codex 세션 리허설 미실행 |
| H-10 | 통과 후 소스·새 파일·테스트 변경 → status → STALE | 필수 / 변경 감지 자동 검사 |
| H-11 | 통과 후 로그·STATE 변경 → status → 기존 제품 근거 유지 | 필수 / test_logs_and_handoff_do_not_invalidate |
| H-12 | 미실행/미확인 → 상태·release → NOT_RUN/PENDING/NOT_READY | 필수 / 자동 검사 + 기록 진실성은 사람 검토 |
| H-13 | 테스트 0개/전부 skip → run → UNVERIFIED/INCOMPLETE | 자동 테스트 조건부 / 0개·전부·일부 skip 자동 검사 |
| H-14 | 대상 없음 또는 예제 범주 → run/release → 차단/미준비 | 조건부 / 대상 부재·example 범주 자동 검사; 실제 AI 연동 미실행 |
| H-15 | 오래된 파일·결과 → run/status → 미검증/현재 실패 유지 | 필수 / 오래된 산출물·최신 실패 자동, 실제 서버 식별은 수동 |
| H-16 | 기존 문서·스테이징 → 재적용 → 바이트·Git index 보존 | 필수 / installer 관련 자동 검사 |
| H-17 | 실제 포함 목록·누락·가짜 비밀파일 → release → 누락/포함 차단 | 필수 / 제출 목록 관련 자동 검사; 완전한 비밀 탐지는 미지원 |
| H-18 | 미읽기·설계 함수·미채택 결정 → 설명 → 구분 표시 | 필수 / 문서·운영 프롬프트 검토, 모델 행동을 프로그램이 보증하지 않음 |

통과 기준은 요구된 자동 시나리오의 실패 0·건너뜀 0, 설치/문서 사용 가능, 미확인 범위의 명시다.
과제 적용 완료 기준은 이보다 크다. 실제 제품 검사·UI·서버·AI·플랫폼 제출은 과제별로 확인해야 한다.
