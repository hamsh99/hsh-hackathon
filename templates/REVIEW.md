# 전체 검증·REVIEW 복습·제출 준비

확인한 코드 기준·관련 미커밋 변경·시각: 미확인

| 구분 | 현재 상태 | 남은 조치·근거 위치 |
|---|---|---|
| 전체 검증 | 미실행 | |
| 내 설명 확인 | 대기 | |
| 제출 준비 점검 | 미점검 | |

세 상태는 별개다. 준비 상태는 준비됨 / 미완료 / 확인 불가로 구분하고 부족한 점을 적는다.
기능 검증·필수 준비 항목이 미완료면 준비됨으로 표시하지 않는다. 이해 확인 대기는 검증 실패가 아니며 독립 점검을 막지 않는다.
기존 라운드의 기능·검사·대화는 링크로 연결한다. 기록 전체를 복사하지 않는다.

## 1. 전체 검증

| 필수 조건·사용자 흐름 | 관련 라운드·기능 | 현재 유효한 검사 근거 | 남은 문제 |
|---|---|---|---|

- 실제 제품 실행 명령·작업 위치·현재 서버/설정 또는 결과 파일:
- 정상 입력 하나 → 라운드 간 처리 → 최종 결과:
- 독립 기대 결과·근거 / 실제 결과:
- 중요한 실패 입력 / 기대 반응 / 실제 반응:
- 이번 전체 실행의 시각·실행자·명령/조작·입력·종료 코드 또는 관찰·필요한 로그 위치:
- 실패 수정·재검사한 범위 / 미실행·차단·검증 한계:

정상 흐름은 실제 진입점부터 최종 결과까지 확인한다. 예: 입력→검색→다운로드→파일 내용 확인. 예시는 실제 서비스에 맞게 바꾼다.
기존 근거가 현재 코드에도 유효하면 재사용한다. 새로 확인한 전체 흐름의 근거만 이 문서에 추가한다.
기능별 통과만으로 전체 연결을 통과 처리하지 않는다. 화면을 직접 보지 않았으면 관찰 주체와 미확인 범위를 적는다.
코드·입력·조건이 바뀌면 영향받은 검사와 전체 흐름을 다시 확인하고 관련 기록·설명도 갱신한다.

## 2. REVIEW 복습

- 사용자·해결한 문제·실제 구현 범위와 제외 범위:
- 입력 → 핵심 규칙·처리 → 결과:
- 실제 핵심 파일·함수 3~5개와 역할:
- 중요한 선택 2~3개·이유·포기한 대안·라운드 대화 근거:
- 요구가 바뀌면 수정할 위치 / 실패할 조건·남은 한계:

Codex는 위 흐름을 짧게 설명하고, 사용자가 결과를 먼저 예상한 뒤 실제 근거와 비교하도록 돕는다.

| 확인할 것 | 내 예상·내 말로 한 설명 | 실제 결과·코드 근거와 비교 | 보완할 부분 |
|---|---|---|---|
| 정상 입력이 결과가 되는 흐름 | 아직 답하지 않음 | | |
| 중요한 실패 입력의 동작 | 아직 답하지 않음 | | |
| 중요한 선택의 이유·포기한 점·한계 | 아직 답하지 않음 | | |

설명을 읽거나 동의했다는 사실만으로 내 설명 확인을 완료하지 않는다. 실제 답변에서 틀리거나 빠진 부분만 보완한다.
전체 검증에서 실행한 결과를 복습에 활용할 수 있다. 추가 조작이 필요한 경우만 다시 실행한다.
복습은 공식적으로 AI 사용이 허용된 시간 안에 수행한다. 답변을 기다리는 동안 독립적인 준비 점검은 계속할 수 있다.

## 3. 제출 준비 점검

실제 확인한 항목만 체크하고 해당 없음은 이유를 적는다. 이 목록은 사람이 확인하는 기록이며 자동 판정 프로그램은 없다.

- [ ] 전체 검증의 필수 조건·실제 제품 흐름·필요한 화면 확인에 미해결 문제가 없다.
- [ ] 변경 이후 영향받은 검사와 라운드 연결을 확인했다.
- [ ] 공식 형식·필수 파일·실행법·의존성·설정·결과 위치가 맞다.
- [ ] 현재 코드와 서버/결과물이 일치하며 오래된 결과를 현재 결과로 쓰지 않는다.
- [ ] 개발용 더미·오류 주입·초기화 버튼과 페이지·라우트·API를 최종 구성에서 제외 또는 차단했다.
- [ ] 개발 확인 화면이 있다면 같은 제품 구현을 사용하며 제품이 테스트 도구에 의존하지 않는다.
- [ ] 원본 데이터가 보존되어 있고 시작 코드의 수정과 구별했다.
- [ ] 모의 응답과 실제 API·AI 응답을 구분했고, 필수 연동은 실제로 확인했다.
- [ ] 실제 수집 범위에서 하네스 원본·임시 파일·민감 설정·불필요한 로그의 포함 여부를 확인했다.

`.gitignore`는 Git 추적 설정이며 플랫폼의 파일 수집 범위를 정하지 않는다. 불필요한 파일은 사용자 자료를 지우지 않도록 확인해서 처리한다.
과제 작업 중 **git push와 외부 저장소 업로드는 금지**한다. API 등 다른 전송 방법으로 우회하지 않는다. 로컬 커밋과 구분한다.

- 준비 판정과 근거:
- 부족한 항목·확인 불가·다음 조치:

준비 점검 결과를 보고하면 하네스의 마무리 절차는 끝난다. 플랫폼 제출 버튼은 사용자가 누른다.
버튼 조작·제출 결과 확인·접수 시각 기록은 수행하지 않는다. 최종 점검 이후 코드·설정이 바뀌면 영향받은 항목을 다시 확인한다.
