# 최종 서비스 설명과 제출 확인

작성 상태: 실제 서비스 미확인 · 확인한 코드 기준/시각: 미확인
마무리 때 실제 코드와 실행 근거를 보고 작성한다. 라운드 기록 전체를 복사하지 않는다.

## 내가 만든 것

- 사용자·해결한 문제·구현 범위:
- 정상 입력 하나 → 실제 처리 순서 → 결과:
- 핵심 파일·함수 3~5개와 역할:
- 중요한 선택 2~3개·이유·포기한 점·라운드 대화 근거:
- 요구가 바뀌면 수정할 위치:
- 검증한 범위·알려진 한계·제외한 기능:

## 직접 따라 확인하기

- 실제 제품 실행 명령·작업 위치·주소 또는 결과 파일:
- 정상 입력 / 내가 예상한 결과 / 실제 결과 / 검사 근거:
- 중요한 실패 입력 / 예상 반응 / 실제 반응 / 검사 근거:
- 내 말로 설명한 내용과 아직 모르는 부분: 확인 전

설명을 읽었다는 사실만으로 직접 설명할 수 있다고 쓰지 않는다. 복습은 공식적으로 AI 사용이 허용된 시간 안에 수행한다.

## 제출 전 확인

실제 확인한 항목만 체크한다. 해당 없음은 이유를 적는다. 체크 표시를 자동으로 검증하는 프로그램은 없다.

- [ ] 공식 필수 조건이 실제 기능·현재 검사 근거와 연결된다.
- [ ] 실제 제품 진입점에서 대표 입력부터 결과까지 실행된다.
- [ ] 변경 이후 영향받은 검사·기존 라운드 연결을 다시 확인했다.
- [ ] 필요한 화면·빈 상태·오류를 실제로 확인했고 현재 코드의 서버가 맞다.
- [ ] 개발용 더미·오류 주입·초기화 버튼뿐 아니라 페이지·라우트·API도 최종 구성에서 제외 또는 차단했다.
- [ ] 개발 확인 화면이 있다면 같은 제품 구현을 사용하고 제품이 테스트 도구에 의존하지 않는다.
- [ ] 원본 데이터가 보존되어 있으며 시작 코드의 변경과 구별했다.
- [ ] 모의 결과와 실제 API·AI 응답을 구분하고, 필수 연동은 실제로 확인했다.
- [ ] 실행법·필수 파일·의존성·결과 위치가 맞고, 실제 제출 범위를 확인했다.
- [ ] 하네스 다운로드 원본·임시 파일·민감 설정·불필요한 로그의 포함 여부를 실제 제출 방식에서 확인했다.

`.gitignore`는 Git의 파일 추적 설정이며 플랫폼 수집·ZIP 포함 여부를 정하지 않는다.
최종 확인 뒤 코드·설정이 바뀌면 영향받은 항목을 다시 확인한다.

- 미완료·확인 불가와 다음 조치:
- 실제 제출 방법·마감:
- 플랫폼에서 확인한 제출 결과: 아직 제출하지 않음
