# 전체 계획

현재 라운드: 미정 · 다음 행동: 문제 원문과 실행 환경 확인
마지막 확인 시각: 미확인 · 시작/마감과 시간대: 미확인

## 목표와 필수 조건

- 사용자와 해결할 문제:
- 입력 → 최종 결과:
- 공식 안내·문제 원문 위치와 읽은 범위:
- 필수 요구사항과 완료조건: 원문 이름이나 번호를 사용하고 담당 라운드를 연결한다.
- 제출 형식·필수 파일·실행 환경:
- 원본 데이터 위치 / 수정할 시작 코드 / 최초 상태 근거:
- 확인한 사실 / 가정 / 사용자 확인이 필요한 것:

## 라운드 표

| 라운드·목표 | 연결할 필수 조건·선행 작업 | 배정 시간 | 상태 요약·근거 문서 |
|---|---|---|---|

아직 라운드는 정하지 않았다. 실제 목표를 정한 뒤 각 문서를 연결한다.
상태 요약은 예정 / 진행 중 / 확인 대기 / 완료 / 차단 / 제외 중 맞는 표현을 사용한다.
세부 기능·검사·결정은 각 라운드 문서에서만 관리한다. 전체 완료는 필요한 기능 연결·현재 검사·사람 확인이 모두 충족된 범위에만 표시한다.

## 범위와 시간

- 반드시 할 것:
- 시간이 남으면 할 것:
- 이번에 제외할 것과 이유:
- 첫 전체 흐름 / 선택 기능 중단 / 최종 확인 / 제출 여유 시점:

## 현재 작업과 기록 위치

- 현재 라운드 문서와 다음 구체 행동:
- 차단·사람 확인 대기: 자세한 내용은 해당 라운드로 연결.
- 기존 문서를 재사용할 경우 실제 경로:
- 중요한 전체 범위 변경과 근거: 라운드 결정과 중복하지 않는다.

자동 상태 관리나 실시간 타이머는 없다. Codex가 라운드 시작·중요 변경·검사 후·중단 때 갱신한다.
새 세션은 현재 라운드의 인계와 실제 Git·파일·서버를 확인한 뒤 재개한다.
