아래 표와 이 요약은 라운드 기록에서 가져온 현재 상태다. 자동 갱신이나 실시간 타이머가 아니다.

## 라운드 표

| 라운드·목표·범위 | 필수 조건·선행 작업 / 배정 시간 | 구현·연결 | 검사 | 사용자 화면·동작 확인 | 상세 근거 |
|---|---|---|---|---|---|

아직 라운드는 정하지 않았다. 과제 범위·의존성·남은 시간에 맞춰 필요한 수의 행을 추가하고 R1부터 순서대로 번호를 붙인다. 라운드 수는 고정하지 않으며, 실제로 만든 상세 문서만 연결한다.
범위는 필수 / 선택 / 제외로 표시한다.
구현·연결: 예정 / 진행 중 / 연결 완료 / 차단.
검사: 미실행 / 통과 / 실패 / 실행 차단 / 재검증 필요 / 해당 없음.
사용자 확인: 미확인 / 확인 완료 / 수정 필요 / 재확인 필요 / 해당 없음.
일부만 통과했으면 '일부 통과·나머지 미실행'처럼 남긴다. 해당 없음의 이유와 검사별 상세 근거는 라운드 문서에 둔다.
검사 통과만으로 라운드 전체를 완료로 보지 않으며 라운드 개수로 제품 완성률을 계산하지 않는다.
세부 기능·검사·결정은 각 라운드 문서에서만 관리한다. 전체 완료는 필요한 기능 연결·현재 검사·사람 확인이 모두 충족된 범위에만 표시한다.

- 중요한 전체 범위 변경과 근거: 라운드 결정과 중복하지 않는다.

## 마무리 안내

- 진행 순서: 전체 검증 → REVIEW 복습 → 제출 준비 점검
- 상세 상태·근거·남은 조치: REVIEW를 만들 때 실제 위치를 연결한다.

마무리의 전체 검증·내 설명 확인·준비 판정은 REVIEW에서만 관리한다. PLAN에 같은 결과표를 복사하지 않는다.
과제 작업 중 git push와 외부 저장소 업로드는 금지한다. 로컬 커밋과 구분한다.
하네스의 범위는 준비 점검까지다. 플랫폼 제출 버튼은 사용자가 누르며 제출 결과 추적은 하지 않는다.

자동 상태 관리나 실시간 타이머는 없다. Codex가 라운드 시작·중요 변경·검사 후·중단 때 갱신한다.
새 세션은 현재 라운드의 인계와 실제 Git·파일·서버를 확인한 뒤 재개한다.
