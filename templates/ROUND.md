| 작업 이름·관련 기능 | 방법·입력 조건 | 독립 기대 결과·근거 | 실제 결과·판정 | 실행 근거 위치 |
|---|---|---|---|---|

작업 이름은 `{{ROUND}} 검사 01`부터 사용한다. 한 검사로 여러 기능의 연결을 확인해도 된다.
방법은 프로젝트의 자동 테스트 / 실제 명령·API 실행 / 사람 화면·파일 확인 중 필요한 것을 선택한다.
판정은 미실행 / 통과 / 실패 / 실행 차단 / 재검증 필요 / 해당 없음(이유)으로 적는다.
검사별 필수 여부와 건너뛴 사유를 방법·입력 조건에 적는다. 실행한 검사가 없거나 필수 검사가 건너뛰어진 범위는 통과로 표시하지 않는다. 아직 실행하지 않은 경우는 미실행, 환경·도구 문제로 실행할 수 없는 경우는 실행 차단이며, 불필요한 검사의 해당 없음과 구별한다.

실행했을 때만 아래 내용을 짧게 추가한다. 같은 코드를 확인한 검사 여러 개는 한 실행 기록으로 묶을 수 있다.

- 대상 검사·시각·실행자·작업 위치:
- 실제 명령 또는 조작 / 사용한 입력:
- 코드 기준: 커밋과 관련 미커밋 변경을 기록한다. 미커밋 변경을 커밋만으로 식별하지 말고 필요하면 관련 diff·파일 해시를 보관한다.
- 기대 결과 / 실제 관찰 / 종료 코드·실행/실패/건너뜀 개수(확인 가능할 때):
- 판정과 한계 / 필요한 긴 로그 위치:

긴 로그는 필요할 때 `docs/rounds/logs/`에 새 파일로 남긴다. 예: `R1-20261031-140000.log`(예시이며 시각의 시간대를 함께 기록).
Codex가 실행·파일 검사와 기록을 맡고, 계획에서 정한 사용자 관찰은 실제 답변을 받아 반영한다. 로그에 비밀정보를 남기지 않는다. 사람이 확인했다는 보고는 자동 UI 검사와 구별한다.
과거 실행은 보존하고 관련 코드·조건이 바뀌면 해당 검사 판정을 재검증 필요로 갱신한다. 이 갱신을 강제하는 프로그램은 없다.

## 내가 이해할 핵심

핵심 동작이 달라진 라운드에서만 짧게 확인한다. 이해 대기는 기능의 구현·검사 상태와 별개이며 다른 작업을 막지 않는다.
