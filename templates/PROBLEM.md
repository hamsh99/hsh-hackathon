# 문제 이해와 설계 근거

마지막 확인 시각: 미확인 · 원문·데이터 기준: 미확인
이 문서는 빈 양식이다. 예시·미확인·잠정 가정을 확정 사실이나 실제 분석 결과로 취급하지 않는다.
작은 과제는 필요한 항목만 짧게 작성한다. 해당 없는 분석·질의는 이유를 적고 억지로 채우지 않는다.

## 1. 쉽게 설명한 문제

- 누가 / 현재 겪는 문제 / 해결하면 달라지는 점:
- 입력 → 필요한 판단·처리 → 사용자에게 보이는 결과:
- 포함할 범위 / 제외할 범위:
- 작은 정상 예시 / 규칙을 위반한 예시:
- 처음 등장하는 어려운 용어와 쉬운 뜻:

## 2. 원문과 확정 요구사항

| 요구사항·원문 번호 | 반드시 지킬 내용·완료조건 | 출처 위치·읽은 범위 | 충돌·확인 필요 |
|---|---|---|---|

원문 번호를 보존한다. 공식 요구사항, 담당자가 확인한 운영 조건, 사용자의 선택, Codex 제안을 구별한다.
출처끼리 충돌하면 우선순위를 확인하고 담당자에게 명확히 묻는다. 담당자 답변이나 분석 결과로 공식 조건을 조용히 덮어쓰지 않는다.
문제 원문은 보존하고 이 문서는 해석·근거·결정의 기록으로 사용한다.

## 3. 데이터 현황과 품질

| 데이터 위치·버전 | 한 행의 의미·주요 열·단위 | 기간·대상·행 수 | 누락·중복·형식·참조 문제 | 확인 근거·미확인 |
|---|---|---|---|---|

- 전체 검사 / 표본 검사 범위와 한계:
- 날짜·시각·시간대, ID 연결, 중복 행의 업무상 의미:
- 원본을 보존한 분석 방법 / 실행 코드·명령 위치:
- 분석 전에 필요한 정제와 그 이유: 원본을 임의로 덮어쓰거나 의미 미확인 중복을 삭제하지 않는다.

CSV 외의 입력도 실제 형식에 맞춰 작성한다. 파일을 읽었다는 사실만으로 품질 검사를 통과했다고 하지 않는다.

## 4. 분석으로 발견한 정보

| 풀려는 질문 | 관측 결과·수치·단위 | 대상·기간·필터·분모 | 계산 근거·코드·입력 버전 | 해석·한계·설계 영향 |
|---|---|---|---|---|

설계 선택에 영향을 주는 분석부터 한다. 필요한 경우 분포·그룹별 차이·기간별 변화·예외·최댓값 등 일부 대상에 집중된 부담을 확인한다.
관측 사실과 해석·원인 가설은 분리한다. 건수와 비율을 혼동하지 않으며 분모가 없으면 비율을 지어내지 않는다.
데이터에서 계산된 통계는 운영 규칙이 아니다. 이전 이용률·평균값을 이유로 원문의 대상이나 필수 조건을 줄이지 않는다.
숫자 예시와 실제 계산 결과를 명확히 구별한다. 실데이터를 보지 못했다면 분석 계획과 미확인으로 남긴다.

## 5. 담당자·시나리오 에이전트 질의

| 질문·발견 배경 | 실제 답변·출처·시점 | 확인된 의미·적용 범위 | 설계에 반영할 내용 | 미해결·추가 확인 |
|---|---|---|---|---|

과제에서 허용하고 사용자가 위임한 채널·범위에서 질문한다. 채널이 없거나 사용할 수 없으면 질문안과 확인 대기로 남긴다.
질문은 발견한 차이, 가능한 해석, 답에 따라 바뀌는 설계를 포함한다. 구현 방법의 정답을 대신 요구하지 않는다.
실제 답변을 받기 전에는 예상 답변·가상의 예시를 확인 완료로 기록하지 않는다.

## 6. 반드시 지킬 조건·개선 목표·설계 인자

인자는 계산이나 판단에 넣는 기준값이다. 모든 정보가 제약조건인 것은 아니다.

| 항목 | 분류 | 값·단위 또는 평가 방법 | 적용 대상·기간 | 근거 위치·판단 주체 | 확정 상태·영향받는 작업 |
|---|---|---|---|---|---|

분류는 반드시 지킬 조건 / 더 좋게 만들 목표 / 데이터 관측 / 설계 가정으로 구분한다.
확정 상태는 확정 / 잠정 가정 / 확인 대기 / 충돌 / 재확인 필요로 적는다. 없는 수치를 임의로 채우지 않는다.

- 반드시 지킬 조건: 허용 범위·경계값·예외와 위반 여부를 확인할 방법.
- 더 좋게 만들 목표: 비교 지표·단위·개선 방향·우선순위·감수할 불편. 가중치를 사용한다면 선택 이유.
- 설계 가정: 추정 방법·근거·한계, 값을 바꾸면 결과가 얼마나 달라지는지 확인할 방법.
- 비교할 기본안과 개선안 / 같은 입력으로 비교할 기준:
- 조건을 만족하는 해가 없을 때의 표시·대응: 조건을 몰래 완화하거나 일부 대상을 누락하지 않는다.

원문의 의무 조건은 목표 점수를 높이기 위해 위반할 수 없다.
최적성이 증명되지 않은 결과는 최적해라고 단정하지 않고, 실행 가능한 개선안과 비교 근거로 설명한다.

## 7. 구현 전에 확인할 판단

| 미확정 논점·왜 중요한가 | 선택지·추천안·영향 | 필요한 조사·작은 비교·확인 주체 | 보류할 작업 | 독립적으로 진행할 작업 |
|---|---|---|---|---|

대상·업무 의미·허용 범위·평가 기준을 바꾸는 판단은 해당 구현 전에 확인한다.
질문에는 선택지와 영향, 가능한 작은 비교 근거를 제시한다. 중요한 운영 조건의 무응답을 승인으로 간주하지 않는다.
쉽게 되돌릴 구현 선택은 허용 범위에서 진행한다. 모든 질문이 끝날 때까지 전체 개발을 멈추지 않는다.

## 8. 변경과 기록 연결

| 변경 시점·입력 기준 | 바뀐 사실·조건·이유 | 영향받는 라운드·설명·검사 | 재분석·재검증 상태 |
|---|---|---|---|

- 전체 계획 위치:
- 상세 분석 코드·결과 위치:
- 구조 설명 위치: 필요한 경우에만 연결.

업무 기준·분석 근거의 원본 기록은 이 문서에 둔다. PLAN은 요약과 링크, 라운드는 실제 구현·검사 근거를 보관한다.
이미 라운드에 기록한 결정은 연결하고 중복 복사하지 않는다. 나중에 라운드가 생겨도 초기 결정을 새 번호로 다시 만들 필요는 없다.
데이터셋·기간·규칙이 바뀌면 영향받은 통계·조건·가정·검사와 구조 설명을 갱신한다.
