## 1. 어떤 문제를 해결하나요?

누가 어떤 불편을 겪고 있으며, 서비스가 무엇을 도와주는지 짧은 문장으로 설명한다.

- 입력 → 필요한 처리 → 사용자가 받는 결과:
- 포함하는 범위 / 이번에 다루지 않는 범위:
**예상 결과 예시 · 설명용 가상 값**

원문과 결과 형식을 처음 읽은 뒤, 상세 분석·라운드 계획 전에 여기에 작은 완성 결과를 그린다. 누가 무엇을 선택하면 무엇을 보게 되는지 일상어로 적는다. 표가 결과라면 행·열·셀의 뜻이 드러나게 몇 칸을 실제로 채운다. 역할별 결과가 다르면 운영자가 보는 전체 결과와 이용자 한 명이 보는 결과를 각각 한 조각 보여준다. 파일 출력이 핵심이면 필요한 필드만 예로 든다.

가상 값은 제공 데이터·실제 배정·검사 통과와 구분한다. 아직 확인할 조건은 예시 옆에 표시하고, 담당자 답변 뒤 영향받은 칸을 갱신한다. 실제 생성 후 라운드 기록에서 예시와 결과를 대조한다.

## 2. 데이터를 보니 무엇이 중요한가요?

| 중요한 발견 | 왜 문제가 되나요? | 풀이에 어떻게 반영하나요? |
|---|---|---|

판단을 바꾸는 발견만 적고 필요한 수치에 단위·대상을 붙인다. 자세한 계산 근거는 하단에서 연결한다.
아직 데이터를 보지 못했다면 결과를 만들지 않고 무엇을 확인해야 하는지 설명한다.

## 3. 반드시 지켜야 할 핵심 조건은 무엇인가요?

현재 유효한 조건을 한국어로 설명하고, 정확한 출처·적용 범위는 아래 근거 항목에 연결한다.
중요한 예외·제한·미확정 부분은 여기서도 바로 보이게 한다. 짧게 만들려고 숨기지 않는다.
원문 조건, 담당자가 확인한 조건, 아직 선택되지 않은 가정을 섞지 않는다.

## 4. 어떤 결과가 더 좋은 결과인가요?

- 규칙을 지키는 결과 중 무엇을 더 개선하려고 하는가:
- 무엇으로 비교하며, 서로 충돌하면 어떤 것을 우선하는가:
- 아직 합의되지 않은 목표나 우선순위:

개선 목표를 달성하기 위해 의무 조건을 어기지 않는다. 원래 수요·대상을 임의로 줄이거나 부족함을 숨기지 않는다.

## 5. 지금 무엇을 판단해야 하나요?

현재 구현에 영향을 주는 질문부터 적는다. 답변된 질문은 현재 기준과 근거에 반영하고 여기에는 남은 판단만 둔다.

- **확인할 것:**
- 왜 지금 필요한가 / 답에 따라 달라지는 결과:
- 선택지 / 추천안과 이유:
- 누구에게 확인할 것인가 / 답변 전 보류할 작업:

질문마다 위 형식을 필요한 만큼 사용한다. 일반적인 기술 구현 선택을 불필요하게 사용자에게 떠넘기지 않는다.
중요한 운영 조건은 무응답을 승인으로 간주하지 않는다.

## 6. 다음에 무엇을 하나요?

- 바로 할 일 / 답변을 기다리는 동안 독립적으로 할 일:
- 전체 진행상황과 해당 라운드: 실제 문서에 경로와 절 이름을 적는다.

## 필요한 경우 확인하는 상세 근거

여기부터는 정확한 조건이나 계산을 확인할 때 읽는다. Codex는 구현 전에 관련 근거를 읽고 요약만으로 규칙을 추정하지 않는다.
같은 역할의 기존 기록이 있으면 복사하지 않고 그 위치를 연결한다. 없는 파일이나 읽지 않은 자료를 근거처럼 연결하지 않는다.

### 현재 조건과 판단의 출처

| 항목·원문 번호 | 분류·확정 상태 | 정확한 값·단위·대상·기간·예외 | 출처·판단 주체 | 영향받는 작업·검사 위치 |
|---|---|---|---|---|

- 분류: 반드시 지킬 조건 / 개선 목표 / 데이터 관측 / 설계 가정.
- 상태: 확정 / 잠정 가정 / 확인 대기 / 충돌 / 재확인 필요.
- 의무 조건의 경계값과 예외, 목표의 비교 방법·우선순위,가정의 추정 방법과 한계를 필요한 항목에 기록한다.
- 공식 원문·실제 담당자 답변·사용자 선택·Codex 제안을 구분한다. 출처가 충돌하면 확인하고 원문을 조용히 덮어쓰지 않는다.
- 원문 요구사항의 누락 여부는 PLAN의 요구사항 연결과 함께 확인한다. 본문의 핵심 요약이 전체 요구사항을 대체하지 않는다.

### 분석 근거와 담당자 답변

| 확인할 내용 | 현재 결론과 한계 | 실제 근거 위치 |
|---|---|---|

상세 통계·분석 코드·입력 버전 또는 해시·실행 결과는 기존 분석 자료를 연결한다.
근거에는 한 행의 의미, 대상·기간·필터·분모·단위·재현 방법·전체 또는 표본 검사 범위·누락과 참조 문제를 필요한 만큼 남긴다.
분모 없는 비율·인과관계를 지어내지 않고, 관측·해석·예시와 실제 계산 결과를 구별한다.
과거 이용률·평균값은 의무 조건을 완화하는 근거가 아니다. 분석용 검사를 제품 검증 통과로 기록하지 않는다.

담당자·시나리오 에이전트 질의는 실제 질문·답변·출처·시점·적용 범위와 남은 질문을 보존한다.
짧은 답변은 이 항목에, 긴 대화는 기존 라운드의 대화 기록 등에 두고 연결한다. 별도 기록 파일을 매번 늘리지 않는다.
과제에서 허용하고 사용자가 위임한 채널·범위에서만 질문한다. 직접 DM 답변, 사용자가 전달한 답변, 추정 답변을 구분한다.
채널이 없거나 답변을 받지 못하면 확인 대기로 남기고 가상의 답변을 사실로 채우지 않는다.

### 변경과 기록 위치

- 현재 원문·데이터 기준 / 마지막 갱신 시각과 시간대:
- 바뀐 기준과 이유, 과거 가정·미채택 대안의 기록 위치:
- 재분석·재검증이 필요한 항목과 해당 라운드:
- 필요할 때 읽을 구조 설명·분석 자료 위치:

현재 기준은 위 표에서 갱신하고 본문 요약도 함께 맞춘다. 과거 조건과 답변을 본문 끝에 계속 붙이지 않는다.
변경 이력은 기존 라운드 기록에 연결한다. 라운드가 아직 없으면 이 항목에 짧게 보존한다.
기존 자료를 옮길 때는 내용을 보존하고 이동 위치를 연결하며, 예전 경로·인계 참조가 끊기지 않게 갱신한다.
