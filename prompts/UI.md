# 사용자 화면 설계와 확인

## 사용할 때

| 시점 | 할 일 |
|---|---|
| 첫 화면을 구현하기 전 | 역할별 작업 순서, 정보 배치, 주요 동작과 화면 상태 설계 |
| 새 화면·중요한 사용 흐름을 변경하기 전 | 기존 흐름과 연결, 권한·입력·오류·완료 상태 검토 |
| 화면 구현·변경 후 | 실제 화면의 정렬·잘림·문구·조작·상태 전환 확인 |

파일이 있다는 이유로 자동 적용되는 것은 아니다. START와 해당 라운드에서 위 조건에 맞을 때 읽는다.
화면 없는 프로그램이나 화면에 영향이 없는 내부 수정에는 적용하지 않는다.
기존 UI가 있으면 구성과 공통 스타일을 먼저 확인하고 불필요하게 전체를 다시 만들지 않는다.

## 요청문

```text
공통 규칙과 PROBLEM의 사용자·업무 기준, PLAN과 현재 라운드의 목표를 읽어줘.
사용자가 수행할 작업 순서를 기준으로 화면을 설계하고, 허용된 범위에서 구현·검증해줘.

1. 역할별 핵심 작업, 각 화면에서 먼저 알아야 할 정보, 가장 중요한 행동을 정해줘.
구현 전에 간단한 화면 배치안을 설명하고, 중요한 사용 흐름에 미확정 판단이 있는지 확인해줘.
이미 결정된 내용이나 쉽게 되돌릴 배치까지 반복 승인받지 마.
2. 관련 입력과 실행 버튼을 가까이 묶고, 열 정렬·간격·입력 높이·버튼 크기를 일관되게 적용해줘.
현재 작업의 주된 행동과 보조 행동을 시각적으로 구분하고, 서로 관련 없는 기능을 한곳에 섞지 마.
3. 버튼은 작업 실행, 토글은 켜짐·꺼짐 상태 변경에 사용해줘.
토글 변경이 즉시 적용되는지, 저장·적용 버튼을 눌러야 하는지 일관되게 표현해줘.
4. 선택 중인 값 / 실제 적용된 값 / 결과 생성에 사용된 값을 구분해줘.
초기 상태·처리 중·성공·오류·결과 없음·재계산 필요 상태를 필요한 흐름에 설계해줘.
실패했을 때 유지되는 데이터와 이전 결과의 의미를 분명히 보여줘.
5. 키보드 이동·초점 표시·입력 레이블·읽기 쉬운 대비를 확인하고 오류를 색상만으로 전달하지 마.
역할에 따른 화면 구분과 실제 서버의 권한 검증을 구별해줘.
지원 화면 크기와 입력·내보내기 방식은 과제 조건을 따르고 임의의 파일 선택창을 추가하지 마.
6. 구현 후 실제 화면에서 잘림·겹침·정렬·버튼 동작과 중요한 상태 전환을 확인해줘.
브라우저 확인 도구가 없으면 내가 확인할 미리보기 포트·조작·기대 결과를 알려줘.
직접 보지 못한 화면은 확인 완료로 기록하지 마.
```

## 기록과 확인

- 배치안·선택 이유·화면 상태는 현재 라운드의 기능·대화에 필요한 만큼만 남긴다.
- 공통 UI 기준이 필요하면 기존 스타일·구성요소를 재사용하고 PLAN에서 위치를 연결한다.
- 실제 화면 검사와 사용자 관찰을 구별한다. 화면이 예쁘다는 설명만으로 사용성 검사를 통과 처리하지 않는다.
- 화면의 주요 변경이 없으면 과거의 유효한 근거를 재사용하고 전체 디자인 검사를 반복하지 않는다.
- 구조도나 설명 자료가 사용자 화면을 대신하지 않으며, 개발 구현 정보를 제품 화면에 불필요하게 노출하지 않는다.
