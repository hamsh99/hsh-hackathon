# 구조를 이해하고 설명하기

## 사용할 때

여러 역할·화면·처리·저장·실행 환경이 연결되어 이해가 필요할 때 적용한다.
설계 전에 제안 구조를 설명하고, 구현 후에는 실제 코드·설정과 맞춘다. 단순 수정마다 네 도식을 모두 다시 만들지 않는다.
기존 설명 문서가 있으면 재사용한다. 없으면 과제 폴더의 docs/ARCHITECTURE.md에 작성하고 PLAN에서 연결한다.

## 요청문

```text
공통 규칙과 PROBLEM의 확정 사실·가정, PLAN의 범위, 현재 코드·실행 설정을 읽어줘.
내가 서비스를 이해하고 나중에 직접 설명할 수 있도록 구조 설명을 작성해줘.

1. 사용자·화면·서버·알고리즘·DB의 역할을 구분하고 처음 나오는 용어를 쉽게 설명해줘.
역할을 나눴다는 이유만으로 각각 별도 서버나 컨테이너로 만들지는 마.
2. 전체 구조도, 사용자 흐름도, 데이터 처리 흐름도, 배포 구성도를 관점별로 작성해줘.
해당 역할·실행 구성이 없는 경우에는 이유를 적고, 없는 구성요소를 억지로 만들지 마.
3. 각 도식 아래에 쉬운 설명과 한 가지 구체적 예시를 붙여줘.
성공 흐름뿐 아니라 중요한 오류·되돌림·오래된 결과의 처리도 필요한 도식에 나타내줘.
4. 확정 요구사항 / 설계 가정 / 미결정 사항과 근거 위치를 구분해줘.
구현 전 제안과 현재 구현을 명확히 나누고, 실제 구현 설명에는 관련 코드·설정과 확인 기준을 연결해줘.
5. 중요한 선택의 이유·포기한 대안·한계와, 요구가 바뀌면 수정할 부분을 설명해줘.
마지막에 내가 직접 설명해 볼 질문을 제시하고, 내 답변 전에는 이해 확인으로 표시하지 마.

도식 원본은 Markdown의 mermaid 코드 블록으로 저장해줘.
외부 플러그인 설치를 필수 조건으로 두지 마.
현재 환경에서 도식이 표시되지 않으면 SVG·PNG 또는 독립 HTML로 볼 수 있게 제공해줘.
표시·변환을 실제 확인하지 못하면 확인 불가와 대안을 알려줘.
```

## 각 도식이 답할 질문

| 도식 | 답할 질문 |
|---|---|
| 전체 구조도 | 누가 어떤 화면을 사용하며, 화면·처리·저장은 어떻게 연결되는가? |
| 사용자 흐름도 | 어떤 순서로 행동하고, 권한·오류·완료에 따라 어디로 이동하는가? |
| 데이터 처리 흐름도 | 입력이 어떻게 검증·변환·계산·저장되고 실패 시 무엇이 유지되는가? |
| 배포 구성도 | 어떤 프로그램이 어느 실행 환경에서 돌아가고, 설정·네트워크·지속 저장은 어떻게 연결되는가? |

배포 구성도는 실행 구성을 설명한다. 실제 외부 배포는 수행하지 않는다.

## 플러그인 없이 저장·열람하기

Mermaid는 글자로 도식을 표현하는 문법과 렌더링 도구이며 Mermaid Chart 같은 외부 플러그인을 필수로 요구하지 않는다.
MD의 mermaid 코드 블록은 텍스트로 저장할 수 있다. 그림으로 보려면 Mermaid를 지원하는 뷰어 또는 렌더러가 필요하다.
지원하지 않는 환경에서는 코드만 보일 수 있으므로 저장과 렌더링 확인을 구별한다.

- MD + Mermaid: 편집 가능한 원본. 현재 뷰어의 지원 여부를 확인한다.
- MD + SVG·PNG: 그림 파일을 함께 보관하고 상대 경로로 참조한다. 보는 사람은 Mermaid 설치가 필요 없다.
- 독립 HTML: 그림을 포함해 외부 CDN·네트워크 없이 볼 수 있게 구성한다.

변환하려면 생성 환경에 렌더러가 필요할 수 있다. 도구가 없으면 간단한 도식은 SVG로 직접 작성하거나 기존 허용 도구를 활용한다.
도식화를 이유로 과제 데이터를 외부 서비스에 업로드하지 않는다. 외부 플러그인·온라인 편집기 연결을 기본 절차로 삼지 않는다.
도식은 짧은 레이블과 읽기 쉬운 방향을 사용하고, 한 줄에 너무 많은 노드를 늘어놓지 않는다. 복잡하면 관점별로 나눈다.
실제 파일·설정과 모순되거나 미구현 기능을 구현된 것처럼 그리지 않는다.

참고: [Mermaid 소개](https://mermaid.js.org/intro/), [Markdown의 Mermaid 코드 블록](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams).
