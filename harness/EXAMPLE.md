# 가상 예제: CSV 품질 이슈 조회

설계 연습 자료이며 실제 서비스 코드·화면은 포함하지 않는다. 실제 과제 조건에 우선하지 않는다.

## 입력과 독립 기대값
| id | line | priority | status |
|---|---|---|---|
| I001 | L1 | high | open |
| I002 | L1 | normal | open |
| I003 | L2 | high | open |
| I004 | L1 | high | open |
| I005 | L1 | high | closed |
| I006 | L2 | normal | closed |
| I007 | L2 | normal | open |

전체 7행. L1+open은 I001/I002/I004, 총 3행·high 2행. 기대값은 표에서 독립 계산한다.

## 연결 계획
| F/R | 사용자 행동·성공 조건 | 선행·범위·시간 | 설계 경로·함수 | 검증·제품 연결 | 초기 상태 |
|---|---|---|---|---|---|
| F-001/R-001 | CSV 선택→7행 또는 입력 오류 | 없음·필수·20~25분 | src/input.py: parse_issues, app.py | T-001 정상/T-002 오류, T-003 실제 입력 영역→목록 | 예정/미실행/미확인 |
| F-002/R-002 | L1+open 선택→3행·high 2건 | F-001·필수·15~20분 | src/rules.py: filter_issues, summarize_issues | T-004 계산/T-005 빈 결과, T-006 실제 필터→목록 | 예정/미실행/미확인 |
| F-003/R-003 | 조회 결과 다운로드→같은 3행 | F-002·필수·15~20분 | src/export.py: export_issues | T-007 CSV 재읽기/T-008 전체 흐름, 실제 파일 열기 | 예정/미실행/미확인 |

차트는 시간이 남으면 추가. 로그인·영구 저장·자동 AI 분류는 이 예제에서 제외한다.
Python 파일명은 설명용 설계안이고 실제 스택은 과제 조사 후 결정한다.

## F-001 상세 카드
- 범위: 파싱·입력 검사·실제 목록·오류 안내. 필터·내보내기는 제외.
- 계약: parse_issues(content: bytes) -> ParseResult. 순수 계산이며 파일 쓰기·API 호출 없음.
- 입력: 최대 1 MiB, UTF-8/BOM, id/line/priority/status 필수. 추가 열은 무시.
- 값: id=I와 3자리 숫자·중복 불가, line=L1/L2, priority=high/normal, status=open/closed.
- 결과: 성공 시 원래 순서의 행 목록. 오류 시 코드·메시지·가능하면 행 번호.
- 빈 파일은 오류, 헤더만 있으면 정상 빈 목록. 일부 잘못된 행을 몰래 버리지 않는다.
- 자동: 정상 7행, 누락 열, 중복, 크기 초과, 인코딩 오류, 헤더만 있음.
- 사람: 실제 업로드·목록·오류·빈 상태·오류 후 이전 결과가 현재 결과처럼 남지 않음.
- 완료: 실제 연결 + 현재 자동 검사 + 필요한 사용자 확인. 미확인은 완료 아님.

## 반복
계약→독립 기대값→최소 테스트→실패 종류 확인→최소 구현→제품 연결→검사→사람 확인→영향 범위 재검증→기록.
실패 2회 또는 10분 진전 없음이면 입력/구현/환경 등 원인을 다시 분류한다.
설명은 실제 입력→경로·함수→결과, 이유, 검증, 한계의 5줄로 남긴다.
