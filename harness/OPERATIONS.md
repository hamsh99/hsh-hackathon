# 상황별 운영 프롬프트

공통 AGENTS.md와 STATE를 먼저 적용한다. 아래에서 현재 상황 하나만 읽는다.
대괄호는 실제 값으로 바꾼다. 기능별 기록은 짧게 유지하고, 사용자 결정을 꾸며 쓰지 않는다.

## 01 새 문제
```text
공통 규칙을 적용해 [과제 안내]·[공식 가이드]·기존 프로젝트를 분석해줘.
아직 구현은 시작하지 마. 마감은 [시간대 포함 시각]이야.
실제 파일·실행 명령·Git 변경·제출 조건을 확인하고 읽지 않은 범위를 밝혀줘.
필수 사용자 흐름을 R-ID/F-ID로 연결하고 전체 요약표와 첫 기능 상세 카드만 작성해줘.
원본 데이터와 수정 가능한 시작 코드를 구분하고 실제 AI 연동 필요 여부를 확인해줘.
필요한 검사 설정과 첫 흐름·최종 확인 시간을 제안해줘.
TASK·STATE를 갱신하고 결과를 크게 바꾸는 불확실성만 기본안과 함께 보고해줘.
```

## 02 기능 구현
```text
공통 규칙과 TASK의 [F-001] 상세 카드를 적용해줘.
관련 계약·코드·테스트만 읽고 독립 기대값을 정해줘.
핵심 규칙·버그는 최소 테스트부터, 단순 표시 변경은 필요한 확인만 수행해줘.
허용 범위에서 최소 구현을 실제 제품 경로에 연결하고 관련 check를 실행해줘.
화면 확인이 필요하면 작업 경로·명령·주소·조작·기대 결과와 확인할 버전을 알려줘.
TASK·STATE·EVIDENCE와 필요한 DECISIONS를 갱신해줘.
이번 범위 밖 기능은 확대하지 말고 실제 흐름·이유·검증·미확인·한계를 짧게 설명해줘.
```

## 03 UI 피드백
```text
[F-ID]에 대한 사용자 피드백은 [내용]이야. 공통 규칙을 적용해줘.
사용자 관찰과 네가 직접 확인한 것을 구분하고 현재 서버·코드 상태를 확인해줘.
표시 수정인지 업무 동작 변경인지 판단한 뒤 영향 범위만 수정해줘.
업무 규칙·기대 결과가 바뀌는 경우에는 변경점을 먼저 알려줘.
관련 검사만 다시 실행하고 새 수동 확인 run과 조작·기대 결과를 전달해줘.
TASK·STATE·EVIDENCE를 갱신하고, 보지 않은 화면을 직접 확인했다고 쓰지 마.
```

## 04 실패 조사
```text
공통 규칙을 적용해 [실행 ID/오류]를 조사해줘. 관련 기능은 [F-ID]야.
계약·실제 입력·관련 코드·해당 로그만 읽고 가장 작은 재현 조건을 찾아줘.
요구사항/구현/입력/환경/외부 연동 중 원인을 분류하고 한 번에 한 가설을 확인해줘.
구현 버그는 재현 검사와 최소 수정으로 처리해줘. 기대값을 구현에 맞춰 바꾸지 마.
같은 접근 두 번 실패 또는 약 10분 진전 없음이면 시도·남은 가설·영향·다음 선택을 보고해줘.
STATE의 B-ID와 EVIDENCE·TASK 상태를 갱신해줘. 더미 성공으로 대체하지 마.
```

## 05 리팩토링
```text
공통 규칙을 적용해 [범위]의 [반복 버그/검증 곤란]을 개선할지 판단해줘.
현재 동작을 지키는 근거와 변경 영향을 먼저 확인해줘.
남은 시간 대비 이점이 작으면 미루고 이유를 기록해줘.
진행한다면 요구 변경과 분리해 최소 수정하고 계약·호출부·테스트를 맞춰줘.
영향받는 검사를 다시 실행하고 DECISIONS·EVIDENCE·TASK의 실제 경로를 갱신해줘.
새 기능·가상 요구용 계층·전체 재작성은 이번 범위에 포함하지 마.
```

## 06 handoff
```text
공통 규칙에 따라 현재 상태를 다음 세션에 넘길 수 있게 정리해줘.
Git·실제 변경 파일·현재 검증 지문·서버 상태를 확인해줘.
STATE에 현재 F-ID·차단·다음 구체 행동과 명령·사용자 확인 대기·서버 확인 시각을 남겨줘.
계약·현재 상태는 TASK, 결정은 DECISIONS, 실행 사실은 EVIDENCE를 참조해줘.
사용자 결정과 미채택 AI 제안을 구분해줘. 서버 자동 종료나 완료 상태 조작은 하지 마.
다음 세션이 읽을 최소 목록과 가장 먼저 확인할 사항을 보고해줘.
```

## 07 재개
```text
공통 규칙과 STATE를 읽고 작업을 재개해줘.
기록을 현재 사실로 가정하지 말고 Git·실제 파일·미커밋 변경·check status·서버를 대조해줘.
오래된 상태는 근거와 함께 바로잡고, 현재 기능의 계약·관련 코드만 추가로 읽어줘.
유효한 검사를 불필요하게 반복하지 말고 재개에 필요한 최소 검사만 실행해줘.
이전 허용 범위의 작업은 계속하고, 목표·업무 규칙 변경이나 실제 차단만 질문해줘.
STATE와 영향받는 TASK 상태를 갱신해줘.
```

## 08 설명
```text
공통 규칙을 적용해 [F-ID/전체 서비스]를 초보자에게 설명해줘. 코드는 변경하지 마.
실제 코드·검증 근거를 확인하고 사용자 입력→파일·함수·데이터→결과를 연결해줘.
선택 이유·대안·실패 처리·검증 한계·요구 변경 시 수정 위치를 설명해줘.
사용자 결정과 Codex 판단을 구분하고, 존재하지 않는 코드나 미실행 검사를 근거로 쓰지 마.
기능별 설명은 짧게, 중요한 결정만 자세히 설명해줘.
전체 설명이면 README와 DECISIONS를 연결해줘. 내가 이해했다고 임의로 기록하지 마.
```

## 09 최종 제출
```text
공통 규칙에 따라 [공식 제출 조건]과 [제출 대상]을 점검해줘.
필수 R-ID→구현→현재 유효한 근거를 대조하고 RELEASE_CHECKLIST를 적용해줘.
실제 제품 실행·원본·개발 도구 제외·제출 파일 누락·임시/비밀정보 포함을 확인해줘.
환경·예제 통과를 제품 통과로 세지 말고 필요한 최종 검사만 실행해줘.
사람 확인은 실제 관찰 후에만 confirm하고 코드가 바뀌면 관련 결과를 다시 확인해줘.
README·TASK·STATE·EVIDENCE를 갱신하고 release 결과와 미완료·차단·대기를 보고해줘.
별도 지시 없는 push·업로드·배포는 하지 마. 제출 완료는 실제 플랫폼에서 확인해줘.
```
