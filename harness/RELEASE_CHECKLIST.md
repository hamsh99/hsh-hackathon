# 최종 사람 검토

아래 항목을 실제 과제·실제 제출 구성에서 확인한 뒤 M-RELEASE를 confirm한다.
해당 없음은 이유와 함께 기록한다. 이 목록을 읽기만 한 것은 확인 완료가 아니다.

- 공식 필수 요구사항 각각이 TASK의 구현·검사와 연결되는가?
- 실제 제품 진입점에서 대표 입력→결과까지 되는가?
- 현재 화면이 현재 프로젝트·코드의 서버인가?
- 개발용 버튼을 숨기는 데 그치지 않고 페이지·라우트·초기화 API도 제외/차단했는가?
- 개발 화면이 있다면 같은 제품 구현을 사용하며 제품이 dev에 의존하지 않는가?
- 정상·빈 결과·중요한 오류 표시를 사람이 실제로 확인했는가?
- 모의 응답·실제 API·실제 AI 결과를 구분했는가? 필수 AI 연동은 실제 호출했는가?
- 원본 해시가 유지되는가? 시작 코드 수정은 원본 데이터 훼손과 구분했는가?
- 실행 명령·필수 파일·의존성·설정 안내로 재현할 수 있는가?
- 제출 목록에서 임시 파일·로그의 비밀정보·로그인 설정을 확인했는가?
- 플랫폼 수집 방식과 로컬 제출 목록이 일치하는가? .gitignore만 믿지 않았는가?
- 기능의 흐름·선택 이유·한계·포기한 범위를 본인이 설명할 수 있는가?
- 사용자 결정과 Codex의 구현 판단을 구분했는가?
- 미실행·차단·사람 확인 대기를 완료로 바꾸지 않았는가?

코드 변경 후 관련 검사를 다시 수행한다. 확인 이후 제출 정책·파일 구성 변경도 점검한다.
release의 READY_FOR_SUBMISSION은 로컬 구성 기준이다. 실제 제출 완료는 플랫폼에서 확인한다.
