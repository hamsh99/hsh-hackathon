# hsh-hackathon · 라운드 하네스 v2.1

Codex 한 세션과 작은 기능을 만들고, 실제 결과를 확인하며, 내가 설명할 수 있게 기록하는 문서 묶음입니다.
평소에는 **전체 계획과 현재 라운드 문서 두 장**을 봅니다. 별도의 Python 설치·검사 프로그램이나 화면 서버는 포함하지 않습니다.

## 시작하기

문제와 코드가 있는 **과제 폴더**에서 내려받습니다. 내려받은 하네스 폴더로 이동하지 않습니다.

```bash
git clone https://github.com/hamsh99/hsh-hackathon.git _harness/hsh-hackathon
```

같은 경로가 이미 있으면 지우거나 다시 clone하지 말고 현재 원본과 변경 여부부터 확인합니다.
이후 **Codex 채팅**에 다음을 전달합니다. 아래는 셸 명령이 아닙니다.

```text
현재 과제 폴더에서 작업해줘.
_harness/hsh-hackathon/AGENTS.md와 _harness/hsh-hackathon/START.md를 읽고
'처음 시작'을 적용해줘. 기존 지침·README·코드·사용자 변경을 보존해줘.
문제의 필수 흐름을 R1·R2로 나누고, 첫 라운드의 기능과 검사를 정리해줘.
전체 계획과 첫 라운드 계획을 보여줘. 아직 서비스 구현은 시작하지 마.
```

Codex가 양식에서 필요한 문서를 준비합니다. 별도의 설치 명령은 없습니다.
공개 저장소 다운로드에는 MCP가 필요하지 않습니다. 제품에 필요한 언어·도구는 과제에 따라 정합니다.

처음부터 마무리까지 따라가는 예시는 [3시간 실행 시나리오](SCENARIO.md)를 참고하세요. 예제이며 실제 과제와 검사 결과는 아닙니다.

## 전체 진행상황을 볼 때

과제 폴더의 **`docs/PLAN.md`**를 열면 현재 단계·라운드·다음 행동·차단 사항과 라운드별 구현·검사·사용자 확인 상태를 볼 수 있습니다.
저장소에는 [PLAN 양식](templates/PLAN.md)이 있으며 실제 과제 시작 때 Codex가 작성합니다. 별도 현황 파일은 추가하지 않습니다.

```text
_harness/hsh-hackathon/START.md의 '전체 진행상황 점검'을 적용해줘.
PLAN을 갱신하고 남은 필수 작업과 바로 다음 행동을 알려줘.
```

Codex가 라운드 종료와 중요한 변경·중단/재개 때 저장하는 요약입니다. 자동 갱신 화면이 아니므로 마지막 확인 시각을 함께 보세요.
상세 근거는 해당 라운드, 마무리의 전체 검증·복습·준비 판정은 REVIEW에서 확인합니다.

## 작업 이름

라운드는 사용자가 실제로 실행할 수 있는 작은 흐름입니다. 첫 라운드부터 입력→처리→결과를 연결합니다.
아래 CSV 사례는 설명용이며 실제 기능이나 검사 결과가 아닙니다.

| 이름 | 의미 | 예시 |
|---|---|---|
| R1 | 첫 번째 구현 묶음 | CSV 선택부터 목록 표시까지 |
| R1 기능 01 | 이 라운드에서 만들 사용자 기능 | CSV를 읽고 목록 표시 |
| R1 검사 01 | 해당 기능을 확인할 사례 | 정상 3행 입력 시 목록 3행 |
| R1 대화 01 | 질문·결정 한 논점 | 빈 파일을 오류로 볼지 결정 |

기능과 검사는 표에서 연결합니다. 한 기능에 검사 여러 개를 연결해도 됩니다.
모든 함수나 대화 한 문장에 번호를 붙이지 않습니다. 같은 논점은 같은 대화 번호에 이어 적고, 삭제한 번호는 재사용하지 않습니다.
기존 문제에 번호가 있으면 원래 번호를 유지하고 대응만 적습니다.

## 실제 과제에 생기는 기록

| 위치 | 역할 | 만드는 시점 |
|---|---|---|
| docs/PLAN.md | 목표·공식 제약·라운드 표·현재 작업 | 처음 |
| docs/rounds/R1.md | 기능·검사·결정·이해·다음 행동 | 해당 라운드가 정해졌을 때 |
| docs/REVIEW.md | 전체 검증·내 설명 확인·제출 준비 점검 | 마무리 때 |
| docs/rounds/logs/ | 필요한 긴 실행 로그 | 짧은 기록만으로 부족할 때 |

R2가 정해지면 R2.md를 추가합니다. 제품 코드는 기존 프로젝트 구조에서 계속 수정하며 라운드별로 복제하지 않습니다.
기존 문서가 같은 역할을 하면 재사용하고 PLAN에 실제 위치를 적습니다. 문서가 있다는 사실은 기능 완료를 뜻하지 않습니다.

## 한 라운드의 순서

1. 기능의 입력·기대 결과와 중요한 실패 사례를 정합니다.
2. Codex가 최소 구현을 실제 사용 경로에 연결합니다.
3. 과제에 맞는 테스트 명령·실제 입력·화면 조작으로 확인합니다.
4. 실패하면 수정하고 영향받은 검사를 다시 수행합니다.
5. 실제 결과·코드 위치·선택 이유·다음 행동을 현재 라운드 문서에 남깁니다.
6. 핵심 흐름을 짧게 설명하고 다음 라운드로 넘어갑니다.

검사는 계산·저장·API·화면 등 실제 위험에 맞춰 고릅니다. 단순 문구 수정마다 테스트 파일을 새로 만들지 않습니다.
Python·JavaScript 등 프로젝트의 기존 검사 도구를 직접 사용합니다. 테스트 코드가 없으면 필요한 부분부터 만들며, 모든 검사를 수동으로 바꾸라는 뜻은 아닙니다.

## 대화창을 바꿀 때

닫기 전에 현재 Codex에 다음을 전달합니다.

```text
_harness/hsh-hackathon/START.md의 '대화창 바꾸기 전' 절차대로 핸드오프를 작성해줘.
중요한 대화·결정·현재 상태를 파일에 저장하고, 저장한 경로와 새 대화창용 요청문을 알려줘.
```

[대화창 바꾸기 전 요청문](START.md#대화창-바꾸기-전)과 [새 대화창 재개 요청문](START.md#새-대화창에서-이어가기)을 함께 준비했습니다.
대화 전문을 자동 저장하는 방식은 아닙니다. Codex가 현재 라운드 문서와 PLAN을 갱신하고 저장했는지 확인합니다.
새 대화는 같은 과제 폴더에서 시작하세요. 별도 핸드오프 문서를 추가할 필요는 없습니다.

## 과제 마무리

| 순서 | 확인할 것 | 기록 |
|---|---|---|
| 전체 검증 | 필수 조건과 실제 입력→최종 결과, 라운드 간 연결, 중요한 실패 사례 | 현재 코드 기준·기대와 실제·검사 근거 |
| REVIEW 복습 | 내가 결과를 예상하고 입력 흐름·선택 이유·한계를 설명할 수 있는지 | 내 설명과 보완할 부분 |
| 제출 준비 점검 | 실행법·필수 파일·원본 보존·개발 도구 제외·민감정보 등 | 확인한 항목과 미완료·다음 조치 |

기존 라운드의 유효한 근거는 링크로 연결합니다. 모든 기록을 다시 복사하지 않습니다.
사용자 이해 대기와 제품의 검증·준비 상태는 별개입니다. 하네스는 준비 점검까지 맡고 플랫폼 제출 버튼은 사용자가 누릅니다.
버튼 조작이나 제출 결과 추적을 Codex 작업에 넣지 않습니다.

**과제 작업 중 `git push`는 금지합니다.** 과제 파일을 API 등 다른 방법으로 외부 저장소에 보내는 것도 금지합니다.
변경을 검토한 로컬 커밋은 사용할 수 있습니다. 이 규칙은 사용자의 운영 요구이며 공식 시험 안내는 별도로 확인합니다.

## 간소화하면서 바뀐 점

- 요구사항·기능·검사의 서로 다른 영문 번호 체계를 없애고 라운드 이름에 한글 역할을 붙였습니다.
- install.py, 검사 설정 JSON, 자체 Python 검사 도구를 현재 배포에서 제외했습니다.
- 상태와 결정, 실행 요약은 현재 라운드 문서에 모았습니다. 전체 계획에는 요약과 링크만 둡니다.
- 코드 변경 감지·로그 수집·제출 준비 판정은 자동으로 수행되지 않습니다. Codex가 실제 변경과 실행 근거를 대조해 갱신합니다.

공식 시험 규정은 제공된 안내로 확인합니다. 이 문서는 시험 규정이 아닙니다.
기존 버전 사용자와 이전 기록은 [MIGRATION.md](MIGRATION.md), 상황별 요청문은 [START.md](START.md)를 참고하세요.
